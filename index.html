Google Search Ranking & Discoverability Capstone

Machine Learning — Search Performance Optimization

Decision-support analysis for identifying webpages that may warrant SEO review.

Abstract

This project asks how search-volume and average-position signals can be used to support the identification of webpages with lower observed click-through rates (CTR). The analysis addresses a practical content-review problem represented by the FlyRank internship dataset: search teams may need to prioritize which webpages deserve human review first. A Random Forest regression model was trained to estimate CTR using search volume and average position, with grouped validation used to reduce the risk of overly optimistic evaluation. On the grouped validation split, the model measured an MAE of 0.5093 compared with 0.6032 for the previous validation result, while the measured R² remained negative at -0.3700. The resulting scores were therefore treated as directional decision-support signals for prioritization rather than proof of causal SEO effects or Google's ranking behavior.

1. Introduction / Problem Statement

Search teams need practical ways to decide which webpages deserve review first. Reviewing every page equally can use time and resources inefficiently.

This reflects the broader content-review problem represented by the FlyRank internship dataset: search teams may have many webpages to evaluate but limited time to review them individually. The purpose of this analysis is therefore to turn available search-performance signals into a ranked review queue that can help humans decide where to look first.

This capstone focuses on a Search Performance Optimization lane. The decision supported by the analysis is: which webpages should be reviewed first based on measured search performance signals?

The intended users are SEO analysts, digital marketers, content teams, and website owners. The output is a ranked review queue rather than an automated publishing or optimization system.

2. Data

The project used the anonymized FlyRank ML Internship search dataset available through the internship workspace. The working analysis used content-level search performance records.

Features used

  • Search volume
  • Average search position
  • Click-through rate (CTR)
  • Client/content grouping information for validation

Public-safety exclusions

Client names, private queries, credentials, raw private exports, and other identifying information were excluded from the public-facing research artifact.

The analysis is intentionally limited to anonymized and aggregated signals suitable for a public portfolio project.

3. Methodology

Research assumptions

  • Search volume and average position contain useful directional information about observed CTR.
  • The model is used for prioritization, not automatic decision-making.
  • Model predictions should be interpreted alongside human review.

Features

The final model used search volume and average position as input features.

Label

CTR was used as the regression target.

Model

A Random Forest Regressor with 100 estimators was used as the final model.

Validation

A grouped train/test split was used, with 20% of the groups held out for testing. This was chosen to provide a more conservative validation design than treating every row as independently interchangeable.

Leakage checks

Features were reviewed for information that would only become available after the decision point. The final feature set was restricted to the search-performance signals used for the modeling task.

The result should therefore be treated as directional prioritization evidence rather than strong predictive performance.

5. Limitations & Honest Framing

  • The model does not establish causation.
  • It does not prove how Google's ranking system works.
  • It does not prove that changing a page will increase CTR.
  • Negative R² means the model's predictive performance remains limited.
  • The ranked queue should not be treated as an automatic optimization decision.
  • Results may change when the data distribution changes.
  • Human review remains necessary before taking content action.
Safe claim: The model provides a measured, directional decision-support signal for prioritizing pages for review.

6. Ranked Recommendations

The action playbook converts model output into a human-reviewed content review queue.

Reason code: LOW_CTR
Review pages with relatively low observed CTR before making content or metadata changes.
Action: Review SEO
Check the page's title, description, search intent alignment, content relevance, and overall search presentation.
Priority: Use the ranked action score to determine which pages should be reviewed first.

Human-review rule

A recommendation should be reviewed by a person before any change is made. The reviewer should consider search intent, content quality, business relevance, existing page history, and other context unavailable to the model.

What should NOT be automated

  • Automatic publishing of content changes
  • Automatic deletion of pages
  • Automatic changes to important metadata
  • Automatic SEO strategy decisions
  • Claims about Google's ranking algorithm
